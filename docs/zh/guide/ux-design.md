# 用户体验设计

> **核心目标**：多端并存，体感合一——用户感觉不到切换服务器，只感觉助理"无处不在"。

## 痛点分析

为什么用户讨厌"切换服务器"？

| 痛点 | 说明 |
|------|------|
| **状态割裂** | 不确定哪个服务器有哪个文件 |
| **配置重复** | 每个服务器都要设置偏好和 Key |
| **认知负载** | 需要判断"这个任务该发给谁" |

## 解决方案

### 意图路由：自动化的"交通指挥"

用户无需手动选择服务器，客户端维护**能力路由表**：

```javascript
// 路由规则示例
{
  "打印": "PC_Node",      // 本地执行
  "整理文件": "PC_Node",
  "查询财报": "FANG_PUB", // 公网服务
  "创意绘图": "FANG_PUB"
}
```

**用户体验**：
- 始终在同一个聊天框说话
- 后台自动完成跨节点任务转发
- 完全透明，无需感知

### 统一身份：数字通行证

**公钥即 ID**：
- 身份基于加密算法，而非服务器账号
- 连接任何节点都保持同一身份

**拎包入住**：
- 个人偏好（主题、快捷方式、Agent 性格）自动同步
- 换个脑子，但不换性格

### 全局搜索：打破孤岛

**联邦查询**：
```
用户搜索 "2024年合同"
  ↓ 并行请求
┌─────────────┬────────────────┐
│  办公室台式机 │  家里 NAS     │
│  3 个结果    │  5 个结果     │
└─────────────┴────────────────┘
  ↓ 聚合呈现
单一界面显示，标注来源
```

用户不需要记得东西在哪，系统帮他找。

## 极速降维

### 淡化"服务器"，强化"能力"

**传统 UI**：
```
已连接至 192.168.1.100
```

**SoloMind UI**：
```
本地执行权限：已就绪 ✓
云端超级算力：已就绪 ✓
```

### 离线容错

当本地节点离线时：
```
家里的执行节点已离线。
是否将文档暂存于云端，待节点上线后自动打印？
[ 暂存 ]  [ 取消 ]
```

## 设计原则

| 原则 | 实现 |
|------|------|
| **单一入口** | 一个聊天框完成所有操作 |
| **透明路由** | 后台自动分流到正确节点 |
| **身份统一** | 跨节点同一个"我" |
| **容错友好** | 离线时优雅降级 |

## 结论

多服务器切换的心智负担，只有在"用户需要做决定"时才会产生。

通过**意图路由表**和**服务抽象化**，我们将复杂的多节点架构转化为：

> 一个分布式、高可用的**个人超级助理**——
> 用户只感觉到助理**无处不在，且无所不能**。
