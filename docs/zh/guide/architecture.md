# 系统架构

SoloMind 采用 **三层解耦架构** 设计，为超级个体提供灵活、可扩展的私域能力管理平台。

## 设计原则

| 原则 | 说明 |
|------|------|
| **私域优先** | 所有数据本地存储，完全自主可控 |
| **三层解耦** | UI、编排、数据彻底分离，各层独立演进 |
| **AI 原生** | 从架构层面为 AI 交互优化 |
| **确定性执行** | AI 做决策，工作流保障执行可靠 |
| **架构即提示词** | 架构设计本身就是为了让 AI 易于理解、复刻和扩展 |

## 各层特性

### 第一层：交互层

- **表现灵活**：UI 层不持有业务逻辑
- **可替换**：今天用手机，明天用 Telegram Bot，同样的助理
- **动态渲染 (Operator Portal)**：管理后台具备“变色龙”特性，能根据后端 `introspection` 自动生成对应的 CRUD 管理面板，无需重复编写管理端代码
- **协议统一**：只要协议一致，界面随时更换

### 第二层：编排层

- **跨语言**：可混合使用 Node.js、Python、Go 编写微服务
- **乐高拼接**：通过 Orchestrator 实现功能组合
- **动态发现**：新服务注册后自动被 AI 感知

```
示例工作流：财务录入 → 邮件通知 → 自动记账 → 支付触发
通过 JSON 配置即可组合，无需重写代码
```

### 第三层：数据层

- **私有化**：数据完全由您掌控
- **跨服务共享**：不同微服务共享 Redis，实现数据互通
- **可迁移**：随时导出备份，系统"灵魂"随数据移动

## 核心组件

| 组件 | 职责 |
|------|------|
| **Router** | 统一 API 入口、权限审计、服务发现 |
| **Agent** | AI 意图识别、参数提取、自然语言理解 |
| **Orchestrator** | 工作流编排、任务派发、步骤执行 |
| **微服务** | 原子能力单元，可独立部署和扩展 |
| **Redis** | 高性能数据存储、状态管理、事件总线 |

## 架构核心竞争力

| 特性 | 说明 |
|------|------|
| **透明性** | 通过 JSON-RPC 2.0 实现所有业务逻辑透明调用 |
| **扩展性** | 基于"挂载"而非"侵入"的功能增加模式 |
| **确定性** | 将 AI 的不确定性通过状态机转化为确定业务结果 |

## AI 原生开发：架构即提示词

SoloMind 的设计理念是**“开发给 AI 看的代码”**。这种架构使得外部 AI (如 Coding Agent) 能够极速理解并扩展系统：

1.  **高内聚自省 (Self-Introspection)**：微服务不需要外部文档。AI 只要阅读每个服务的 `introspection.js`，就能明白接口契约。
2.  **小样本复刻 (Few-shot Replay)**：提供 `api/sample` 作为标准模板。AI 可以在不理解全局代码的情况下，通过模仿 Sample 快速产出 100% 符合标准的子服务。
3.  **协议驱动 UI (Protocol-Driven UI)**：后端定义数据结构后，前端 `SummaryCard` 会根据返回的元数据自动渲染卡片。这意味着 AI 开发者只需关注后端逻辑，前端 UI “顺便”就做好了。

4.  **测试即配置 (Test as Configuration)**：抛弃脆弱的代码级单测。SoloMind 采用 YAML 数据驱动测试架构，将测试用例与业务逻辑解耦。AI 只需生成简单的 `input/expect` 数据对，即可完成后端逻辑的回归验证。

> **核心哲学**：UI 是门脸，数据是灵魂，编排是连接两者的万能胶。而这一切，都应是 AI 触手可及、开箱即用的。
