# 系统架构

SoloMind 采用 **三层解耦架构** 设计，为超级个体提供灵活、可扩展的私域能力管理平台。

## 设计原则

| 原则 | 说明 |
|------|------|
| **私域优先** | 所有数据本地存储，完全自主可控 |
| **三层解耦** | UI、编排、数据彻底分离，各层独立演进 |
| **AI 原生** | 从架构层面为 AI 交互优化 |
| **确定性执行** | AI 做决策，工作流保障执行可靠 |

## 各层特性

### 第一层：交互层

- **表现灵活**：UI 层不持有业务逻辑
- **可替换**：今天用手机，明天用 Telegram Bot，同样的助理
- **协议统一**：只要协议一致，界面随时更换

### 第二层：编排层

- **跨语言**：可混合使用 Node.js、Python、Go 编写微服务
- **乐高拼接**：通过 Orchestrator 实现功能组合
- **动态发现**：新服务注册后自动被 AI 感知

```
示例工作流：财务录入 → 邮件通知 → 自动记账 → 支付触发
通过 JSON 配置即可组合，无需重写代码
```

### 第三层：数据层

- **私有化**：数据完全由您掌控
- **跨服务共享**：不同微服务共享 Redis，实现数据互通
- **可迁移**：随时导出备份，系统"灵魂"随数据移动

## 核心组件

| 组件 | 职责 |
|------|------|
| **Router** | 统一 API 入口、权限审计、服务发现 |
| **Agent** | AI 意图识别、参数提取、自然语言理解 |
| **Orchestrator** | 工作流编排、任务派发、步骤执行 |
| **微服务** | 原子能力单元，可独立部署和扩展 |
| **Redis** | 高性能数据存储、状态管理、事件总线 |

## 架构核心竞争力

| 特性 | 说明 |
|------|------|
| **透明性** | 通过 JSON-RPC 2.0 实现所有业务逻辑透明调用 |
| **扩展性** | 基于"挂载"而非"侵入"的功能增加模式 |
| **确定性** | 将 AI 的不确定性通过状态机转化为确定业务结果 |

> **核心哲学**：UI 是门脸，数据是灵魂，编排是连接两者的万能胶。
