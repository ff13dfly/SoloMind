# AI 在系统中的角色

> AI 不是"聊天挂件"，而是贯穿运行态和开发态的**核心驱动引擎**。

## AI 的三重角色

| 角色 | 场景 | 说明 |
|------|------|------|
| **指挥官** | 运行时 | 决定做什么，将自然语言转为 RPC 调用 |
| **翻译官** | 运行时 | 让机器听懂人话，参数提取与补全 |
| **工程师** | 开发时 | 辅助生成代码、测试用例、UI 元数据 |

## 运行态：AI 是系统的 CPU

### 意图路由

```
用户: "帮我把上个月的财报打出来"
  ↓ AI 解析
RPC: finance.report.get + printer.print
```

- **依赖度**：100%
- **价值**：用户无需记忆 API，说人话即可

### 参数提取与补全

当用户说"下周二和张总开会"时：
- AI 识别时间："下周二" → 具体日期
- AI 识别人物："张总" → 联系人 ID
- 缺参追问：若缺少会议室，AI 会问"在哪里开？"

### 动态逻辑合成

当没有现成模板时：
1. AI 读取 `system.capabilities`
2. 像搭乐高一样现场编写 JSON 工作流
3. 系统获得"无限扩展性"

## 开发态：AI 是超级生产力

### 微服务适配器生成

对接老旧 ERP 系统的传统方式：
- 程序员读文档 → 手写代码 → 2 天

AI 辅助方式：
1. 将 API 文档喂给 LLM
2. 要求生成符合 JSON-RPC 规范的适配器
3. AI 自动生成 90% 可用代码
4. 人类做最后测试和微调

**效率提升**：10 倍以上

### 测试用例生成

根据微服务代码，AI 自动生成：
- 单元测试（Jest）
- 集成测试脚本
- 边界条件覆盖

### UI 元数据生成

根据 API 返回结构，AI 推荐最佳展示方式：
- 列表数据 → 表格组件
- 统计数据 → 图表组件
- 状态数据 → 卡片组件

## AI 渗透率分析

| 层面 | 传统软件 | SoloMind | AI 渗透率 |
|------|----------|----------|:---------:|
| **交互层** | 鼠标点击/表单 | 自然语言/意图 | **100%** |
| **逻辑层** | 硬编码 if/else | 动态编排/自愈 | **60%** |
| **数据层** | SQL 查询 | 向量检索/RAG | **40%** |
| **开发层** | 人工手写 | AI 辅助生成 | **80%** |

## 关键设计：AI 是可替换的

```
┌─────────────────────────────────────┐
│  AI 层（可替换/升级）               │
│  Qwen / Gemini / GPT / 本地模型     │
└─────────────────┬───────────────────┘
                  ↓ 输出: 工作流 ID + 结构化参数
┌─────────────────┴───────────────────┐
│  工作流层（确定性执行）             │
│  JSON 定义的步骤链                  │
└─────────────────┬───────────────────┘
                  ↓ JSON-RPC 调用
┌─────────────────┴───────────────────┐
│  微服务层（业务资产）               │
│  稳定的 API 契约                    │
└─────────────────────────────────────┘
```

**价值**：
- 升级模型无需重写业务代码
- 更强的模型 = 更精准的理解、更少的确认
- 今天的开发投入在 5 年后依然有效
