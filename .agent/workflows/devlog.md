# 开发日志 (Devlog) 编写规范

开发日志用于记录通过 AI 对话完成项目开发的过程。

## 1. 文件命名

```
devlog/YYYY-MM-DD-简短标题.md
```

示例：`2026-01-19-docs-setup.md`

## 2. 文档结构

```markdown
# YYYY-MM-DD: 标题

> 本文记录了通过纯 AI 对话完成的开发过程。

## 对话目标

一句话描述本次对话要完成的事情。

## 对话过程

### 第 N 轮：小标题

**我说**：用户的原话或意图摘要

**AI 做了**：
- 具体操作 1
- 具体操作 2

---

（重复多轮...）

## 本次对话产出

| 类型 | 数量 |
|------|------|
| 新建文件 | X |
| 修改文件 | X |
| 代码行数 | X |

## 经验总结

- 踩过的坑
- 学到的技巧
- 对 AI 协作的感悟

## 待办

- [ ] 下一步计划
```

## 3. 编写要点

| 要点 | 说明 |
|------|------|
| **展示对话流** | 用「我说 → AI 做了」格式，让读者能复现 |
| **保留原意** | 用户指令用接近原话的方式表达 |
| **突出决策** | 记录为什么选择某个方案 |
| **量化产出** | 用表格列出文件数、代码行数 |
| **诚实记录** | 包括失败和修复过程 |

## 4. 媒体嵌入

如有录制视频或截图，嵌入到相关章节：

```markdown
**录制演示**：
![docs_site_demo](/path/to/recording.webp)
```

## 5. 触发时机

当用户说以下内容时，应主动询问是否需要写 devlog：
- "今天的工作记录一下"
- "总结下我们做了什么"
- "写个开发日志"

## 6. Git 提交

> [!IMPORTANT]
> devlog 文件的 Git 提交需用户明确指令，不得自动提交。
